# 0011: Java 25 (LTS), and the runtime features it buys

## Context
The service started on Java 21. Java 25 is the next long-term-support release, and three of its
runtime changes since 21 apply directly to this service. Language features alone would not justify
a migration; these do.

## Decision
Build and run on Java 25. Maven Enforcer fails the build on an older JDK.

| Change (JEP) | Why it matters here | How it is used | Measured |
|---|---|---|---|
| Virtual threads no longer pin on `synchronized` (JEP 491, JDK 24) | Requests run on virtual threads (`spring.threads.virtual.enabled`). The semantic cache, conversation memory, in-memory store and rate-limit buckets use `synchronized`; on 21, blocking inside them pinned a carrier thread | No code change. On 21 the fix would have been rewriting each to `ReentrantLock` | Not separately benchmarked |
| AOT cache with one-step training (JEP 483, 514, 515) | Classes are loaded, linked and method-profiled ahead of time | The Dockerfile records `app.aot` in a training run (`-Dspring.context.exit=onRefresh`) and starts with `-XX:AOTCache` | Startup 4.2 s → 1.9 s |
| Compact object headers (JEP 519, product feature in 25) | 8-byte object headers instead of 12 or 16 | `-XX:+UseCompactObjectHeaders` in `JAVA_OPTS` | Live heap after loading 480 documents: 64.2 → 59.6 MB (−7%) |

Details and method are in `docs/PERFORMANCE.md`.

## Pitfalls found while migrating
- **Stale class files:** after changing the release level, an incremental build kept Java 21
  bytecode (major version 65) while every test passed. A clean build produces 69. CI always builds
  clean.
- **Silent AOT cache rejection:** the cache only works with the exact flags it was trained with.
  Training without compact headers and running with them logs "Unable to use AOT cache" as a
  warning, and startup quietly returned to 4.2 s. The Dockerfile trains and runs with the same
  `JAVA_OPTS`.
- **JDK warnings that will become errors:** Mockito's agent was attaching itself dynamically. It is
  now loaded with `-javaagent` in Surefire. Maven 3.9's Guice called `sun.misc.Unsafe`; the wrapper
  is now on Maven 3.10.1. The build log has no JVM warnings.
- **The JRE image has no HTTP client,** so the container's `HEALTHCHECK` could never pass. `curl` is
  now installed.

## Not adopted yet
- **Structured concurrency** (JEP 505) would be the right tool for the two search legs (cancel the
  other leg on failure, one scope), but it is still a preview in 25. `CompletableFuture` on a
  virtual-thread executor stays until it is final.
- **Scoped values** (JEP 506, final): there is no per-request context that is passed through
  thread-locals today, so there is nothing to replace.
- **Generational Shenandoah and ZGC:** with heaps under 1 GB and sub-100 ms requests, G1's defaults
  are adequate; revisit with production heap and latency profiles.
